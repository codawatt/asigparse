# OCR engine benchmark: OneOCR vs Tesseract

_Generated by `backend/scripts/benchmark_ocr.py` on 2026-11-12._

## Setup

- Machine: Windows-11-10.0.26200-SP0, Intel64 Family 6 Model 186 Stepping 2, GenuineIntel, Python 3.13.15
- Tesseract: 5.5.3 (`--psm 6`, `ron+eng`, with grayscale/upscale/autocontrast preprocessing)
- OneOCR: Copied from Snipping Tool 11.2608.41.0 (X64) on 2026-11-11T22:20:05 (colour image as decoded; only images < 900 px wide are upscaled). `oneocr+preprocess` = same engine fed the Tesseract preprocessing (A/B test).
- Data: 3 synthetic sample sets (CI 1997, CEI, three talon layouts incl. a PDF), 42 ground-truth fields per variant, 11 variants → 462 field checks and 66 documents per engine.
- Each case runs the **full pipeline** (decode → OCR → parsing → validation), i.e. it measures what the operator would see, not raw character accuracy.

**Caveat:** all images are synthetic renders of fictitious data (no real documents may be used). Real documents add guilloche backgrounds, holograms and wear; absolute numbers will be lower. The comparison between engines on identical inputs is the meaningful part.

- `phone_photo`: background, 3.5° rotation, blur 1.3 px, noise, 65% scale, JPEG q70
- `perspective`: keystone distortion (~6% top inset), JPEG q85
- `low_res_35pct`: downscaled to 35% (≈600 px wide)
- `blur_2px`: Gaussian blur radius 2.2 px
- `dark_low_contrast`: contrast ×0.45, brightness ×0.5
- `jpeg_q18`: 60% scale, JPEG quality 18
- `glare`: bright elliptical reflection over the right-centre area
- `low_res_20pct`: downscaled to 20% (≈350 px wide; text ≈ 6–8 px high)
- `blur_3_5px`: Gaussian blur radius 3.5 px
- `worst_case`: perspective + phone photo + extra blur 1.5 px + contrast ×0.6 + 60% scale + JPEG q35
