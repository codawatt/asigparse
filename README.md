# AsigParse OCR (MVP)

Turns a photo or scan of a **Romanian identity card** and a **vehicle registration certificate (talon)** into
validated, operator-confirmed JSON for insurance quote pre-fill. It follows
[`docs/AsigParse_OCR_Design_Doc_MVP.pdf`](docs/AsigParse_OCR_Design_Doc_MVP.pdf) and the contract in
[`docs/AsigParse_exemplu_payload.json`](docs/AsigParse_exemplu_payload.json).

The flow is: upload, then local OCR, field mapping, deterministic validation, an editable review with uncertain
values highlighted, operator confirmation, JSON export and a **demonstration** RCA quote form.

**OCR engines.** The default is **OneOCR**, the offline engine shipped with Windows 11 Snipping Tool. **Tesseract 5**
is the portable fallback. On our synthetic benchmark, OneOCR got 95.0% of fields correct against 64.9% for
Tesseract, with 0 vs 1 unflagged wrong values, at about 0.21 s vs 1.9 s per document. See
[docs/OCR_ENGINE.md](docs/OCR_ENGINE.md) for the decision, its risks and its licensing caveats, and
[docs/OCR_BENCHMARK.md](docs/OCR_BENCHMARK.md) for the full numbers.

> All sample documents in `backend/samples/` are **synthetic**: they are generated by a script, marked
> SPECIMEN / DATE FICTIVE, and contain fictitious people, IDs, CNPs and vehicles. Do not commit real documents.

## 1. Prerequisites

| Tool | Version used | Notes |
|---|---|---|
| Python | 3.11 – 3.13 (tested 3.13) | backend |
| Node.js | 20+ (tested 24) | frontend |
| OneOCR (recommended, Windows x64) | Snipping Tool 11.2608 (tested) | copied from **your own** Snipping Tool installation; not in the repo |
| Tesseract OCR (fallback / non-Windows) | 5.x (tested 5.5.3) | needs the **`ron`** and **`eng`** language data (`osd` is optional and enables auto-rotation) |

You need at least one of the two engines. With both installed you can compare them per upload in the UI.

### Installing OneOCR (Windows 11)

Snipping Tool must be installed and up to date (Microsoft Store). This copies its three OCR files into
`backend/vendor/oneocr/` (gitignored) and checks their Microsoft signatures:
```bash
powershell -NoProfile -ExecutionPolicy Bypass -File backend/scripts/setup_oneocr.ps1
```
To use the files from another folder, set `ASIGPARSE_ONEOCR_DIR`. OneOCR uses an **undocumented** interface; read
[docs/OCR_ENGINE.md](docs/OCR_ENGINE.md) before any production use.

### Installing Tesseract

**Windows: MSYS2 (no admin rights, includes Romanian data):**
```bash
C:\msys64\usr\bin\pacman.exe -S --needed mingw-w64-ucrt-x86_64-tesseract-ocr mingw-w64-ucrt-x86_64-tesseract-data-ron mingw-w64-ucrt-x86_64-tesseract-data-eng
```

**Windows: UB-Mannheim installer:**
```bash
winget install UB-Mannheim.TesseractOCR
```
Select "Romanian" under *Additional language data* in the installer. You can also copy
[`ron.traineddata`](https://github.com/tesseract-ocr/tessdata_fast/raw/main/ron.traineddata) into
`C:\Program Files\Tesseract-OCR\tessdata\`.

**macOS:**
```bash
brew install tesseract tesseract-lang
```

**Debian/Ubuntu:**
```bash
sudo apt-get install -y tesseract-ocr tesseract-ocr-ron tesseract-ocr-eng
```

The backend looks for `tesseract` in this order: the `ASIGPARSE_TESSERACT_CMD` environment variable, then `PATH`, then the
default Windows locations (`C:\Program Files\Tesseract-OCR`, `C:\msys64\ucrt64\bin`), then `/usr/bin` and `/opt/homebrew/bin`.
Check what was detected at `GET /api/v1/health`, which lists both engines with their availability.

## 2. Setup and run

### Backend (FastAPI, port 8000)

Windows (PowerShell):
```bash
cd backend
py -3.13 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

macOS / Linux:
```bash
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

The API docs (OpenAPI) are at http://127.0.0.1:8000/docs.

### Frontend (React + Vite + Tailwind, port 5173)

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. Vite proxies `/api` to `http://127.0.0.1:8000`. To use another backend, set
`ASIGPARSE_API_URL` before running `npm run dev`.

### Tests

```bash
cd backend
.venv\Scripts\python -m pytest
```
(on macOS/Linux use `.venv/bin/python -m pytest`)

The suite currently has 114 tests:

- `tests/test_validators.py`: CNP checksum, date and county rules; VIN length and forbidden characters (every
  wrong length is flagged); registration-number formats; dates; fuel mapping; names; MRZ check digits.
- `tests/test_parsers.py`: identity and registration parsers on synthetic OCR output. Covers two-column layouts,
  stacked "code above value" layouts, codes glued to their values, MRZ fallback, the CEI without an address,
  holder ≠ owner, low-confidence flags and illegible codes. Also real-world layouts rebuilt with **fictitious**
  values: the CEI front/back with its 3-line MRZ, and the 2024+ talon with owner block, "C2=C1" box and back-page
  legend.
- `tests/test_api.py`: extraction errors (400 bad type / corrupt / empty, 413 too large, 422 unreadable /
  unidentified / duplicate type, 500 OCR missing). Also the confirm flow (corrections, blocking errors,
  `acknowledge_issues`, CNP exclusion, 404 on an expired session), the dry-run validate endpoint and the
  sample whitelist. These tests use a fake OCR engine, so they run without Tesseract.
- `tests/test_ocr_e2e.py`: **real OCR** with each installed engine (OneOCR and Tesseract) over every synthetic
  sample set, compared field by field with the ground truth in `samples/manifest.json`, plus sideways and
  upside-down pages for OneOCR. An engine that isn't installed is skipped.

Frontend type check and production build:
```bash
cd frontend
npm run build
```

### OCR benchmark

```bash
cd backend
.venv\Scripts\python scripts/benchmark_ocr.py --ab-preprocess --out ../docs/OCR_BENCHMARK.md
```
This runs each installed engine through the full pipeline on 11 conditions (original, phone photo, perspective,
low resolution, blur, dark, heavy JPEG, glare and harder variants) and writes accuracy, silent-error and timing
tables. It takes about 3 minutes, mostly in Tesseract.

### Benchmark on real documents (local only)

Real IDs and certificates contain personal data, so they **must never be committed**. `docs/acte/` and
`backend/benchmarks/real/` are gitignored. Put the files in `docs/acte/` and describe them in
`docs/acte/ground_truth.json` (format in the docstring of `backend/scripts/benchmark_real.py`), then run:
```bash
cd backend
.venv\Scripts\python scripts/benchmark_real.py --out ../docs/OCR_BENCHMARK_REAL.md
```
Each document runs as received and under 8 simulated capture conditions (phone photo, perspective, glare, dark,
blur, heavy JPEG, half resolution, rotated 90°). The markdown report is **anonymised**: categories, field names and
percentages only. Every value-level miss is written only to the gitignored `backend/benchmarks/real/details.log`.
It takes about 15 minutes, mostly in Tesseract.

### Regenerating the synthetic samples (optional)

```bash
cd backend
.venv\Scripts\python scripts/generate_samples.py
```

## 3. Demo script (about 2 minutes)

1. Start the backend and the frontend, then open http://localhost:5173. The header should show
   `OCR implicit: OneOCR`. If it shows Tesseract, run `setup_oneocr.ps1`. The **Motor OCR** selector on the upload
   screen switches engines per request, which is handy for comparing them on the same document.
2. In **Seturi demo sintetice**, click **"Caz standard"**. Two synthetic files load into the upload zones.
   They go through the same real OCR as any upload; nothing is pre-filled. Click **Procesează documentele**
   (about 2–3 s per document).
3. **Review**: fields are grouped as Persoană / Act / Vehicul / Date tehnice / Titular C.1 / Proprietar C.2.
   Each field shows a status badge (*Extras*, *Lipsă*, *Necesită verificare*, *Nu apare pe act*, *Corectat*),
   its OCR confidence and its source code (`talon · E`, `CI · CNP` …). C.2 is absent, so the owner is reported
   as **not assumed** rather than copied from the holder.
4. Correct a value on purpose (for example change *Model* to `LOGAN MCV`). The field turns *Corectat* and shows the
   original OCR value with a "revino" (revert) link. Click **Revalidează** to re-run the server-side checks.
5. Tick "Am verificat…" and click **Confirmă și exportă JSON**. The JSON has `status: "confirmed"` and the
   edited field has `source: "operator"`. Use **Copiază** or **Descarcă .json**.
6. In the **demo RCA quote form**, fields are pre-filled from the JSON. **Generează cererea demonstrativă**
   shows a sample insurer-adapter request. No premium is calculated and nothing is sent anywhere.
7. Click **Proces nou** and try **"CEI fără domiciliu…"**. It shows a CNP with an invalid checksum (an error that
   blocks confirmation unless you correct it or explicitly acknowledge it), an expired document, an address
   *not present on a CEI* (null, never guessed), a company as holder (≠ the person) and an electric vehicle
   without P.1.
8. **"Fotografie înclinată…"** shows a rotated, blurred JPEG photo plus a PDF certificate with a different layout,
   where the leasing company (C.2) differs from the holder (C.1).

## 4. What is genuinely functional

- **Real OCR, two interchangeable local engines**: OneOCR (default; about 0.2 s per document; handles rotation
  itself) or Tesseract (grayscale/upscale/autocontrast preprocessing and OSD rotation). Both share one `OcrEngine`
  interface and the same parsers. Supports JPG/PNG and PDF up to 2 pages rendered at 300 DPI. A quality check
  reports blur, low resolution and bad exposure.
- **Document classification by content**: if the files were uploaded in swapped slots, they are reassigned (with an
  info notice). Unidentifiable images return 422, unreadable images return 422, and two files of the same type
  return 422.
- **Identity card (CI model 1997)**: column-aware parsing of the trilingual labels (name, given name, address,
  validity) and of SERIA/NR and the CNP. The **MRZ** (TD2) is parsed with check digits. It is used as a fallback
  and a cross-check (name, and birth date / sex against the CNP). OCR character confusions in the MRZ are corrected
  only when the check digit then verifies.
- **Registration certificate**: parsing of the harmonised codes A, B, C.1.1–3, C.2.1–3, D.1–3, E, F.1, J, P.1–3,
  R, S.1. It handles code-and-value on the same line, two-column layouts, a code printed above its value, and codes
  glued to values (`P.11598`). An illegible code is reported as unassigned text, never guessed.
- **Validation**: CNP (format, date, county, checksum); VIN (17 characters, no I/O/Q; a suggestion is offered but
  never auto-applied); RO plate formats (unusual or historic formats give a warning, not a rejection); ISO dates;
  positive and plausible cc/kW/mass/seats; fuel enum; expired ID; name sanity; holder ≠ insured person (info).
- **Uncertainty handling**: each field has a confidence (mean of Tesseract word confidences). Below the
  threshold (default 0.85) it is marked `review_required`. Missing values are `null` with a reason.
- **Review UI**: editable fields with highlights (amber = review, red = error, blue = corrected), source preview
  with zoom, raw OCR text on demand, a server-side re-validation (`POST /api/v1/validate`), an optional CNP exclusion
  (data minimisation), and confirmation that requires the operator's explicit check.
- **Export**: a confirmed JSON (`schema_version 1.0.0`, every key of the sample contract plus additive fields), with
  copy and download.
- **Demo quote form**: pre-filled from the confirmed JSON and clearly labelled DEMO, with **no prices**.
- **Privacy**: everything is processed in memory and no image is written by the app. The extraction result is kept in
  memory for at most 30 minutes, for the confirm step. Logs contain only IDs, counts and timings, and a redacting
  filter masks any CNP-like or VIN-like token. Validation errors never echo the request body.

## 5. Known limitations (honest list)

- **Real-document accuracy rests on a very small set**: 8 files (3 distinct CEI, 1 CI 1997, 2 certificates; scans,
  screenshots and one phone photo), see [docs/OCR_BENCHMARK_REAL.md](docs/OCR_BENCHMARK_REAL.md). With OneOCR, the
  original files reach 94.3% of fields correct and 77.0% averaged over all simulated capture conditions. That's an
  indication, not a statistically solid figure, and the ≥ 90% target in the design doc is only met on clean
  originals.
- **OneOCR is unofficial and Windows-only.** It depends on Snipping Tool's DLLs through a reverse-engineered
  interface, may break when Snipping Tool updates, and its licence terms for this use have **not** been reviewed.
  Tesseract remains the supported fallback.
- **Talon versions**: the parser handles the 2024+ certificate tested (owner block C.2, "C2=C1" box, back-page legend)
  and the older single-column layouts used in the samples. Other print versions may need rules. Single-letter codes
  (A, B, E, J, R) are read from the shape of their value (plate, date, VIN, category, known colour).
- **The "C2=C1" check box can't be read reliably** (ticked vs empty). The holder is therefore never filled
  automatically from the owner. The operator gets a warning with a one-click suggestion.
- **CEI** (electronic card) is supported: front labels, 2-letter + 7-digit document number, and the 3-line TD1
  MRZ with check digits and full CNP cross-check. The address is never extracted from a CEI, because it is not
  printed on it. **CIS** (simple card) is only detected, not specifically parsed.
- **Residual OCR confusions**, such as `l`/`I` in an address abbreviation ("Bl." read as "BI."), pass validation and
  are the main remaining source of unflagged errors on real data. The operator review stays mandatory.
- **No explicit deskew or perspective correction.** OneOCR tolerates the tested 3.5° tilt and keystone, and sideways
  or upside-down pages are turned upright automatically. Tesseract degrades on all of these. The quality check
  warns the operator to take the photo again.
- **The confidence score is technical OCR uncertainty**, not document authenticity. There is no forgery detection,
  NFC/chip reading or check against official registries.
- **The VIN check digit** (position 9, mandatory only in North America) is not checked.
- **The 2-digit "issued" year** on the CI is ignored; only the 4-digit expiry date is used.
- Processing is **synchronous, single process**, with no queue or idempotency key, and the in-memory store is lost
  on restart (`/confirm` then returns 404 with a clear message). There is no authentication or TLS: **this is not
  for production**.
- The UI is in Romanian and the code and README are in English.

## 6. API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/v1/health` | OCR engine availability, version, languages, threshold |
| POST | `/api/v1/extract` | multipart `identity_image` and/or `registration_image` (JPG/PNG/PDF). Optional `?include_ocr_text=true`, `?engine=oneocr\|tesseract` |
| POST | `/api/v1/validate` | dry-run validation of operator edits (same body as confirm) |
| POST | `/api/v1/confirm` | `{processing_id, corrected_person, corrected_vehicle, acknowledge_issues?, exclude_national_id?}` |
| DELETE | `/api/v1/processing/{id}` | discard the in-memory result |
| GET | `/api/v1/schema` | JSON Schema of the payload |
| GET | `/api/v1/samples`, `/api/v1/samples/{file}` | synthetic demo files (whitelisted) |

Errors use the form `{"error": {"code", "message", "document"}}`:
**400** `UNSUPPORTED_FILE_TYPE` / `CORRUPT_FILE` / `EMPTY_FILE` / `NO_FILES`, **413** `FILE_TOO_LARGE`,
**422** `UNREADABLE_DOCUMENT` / `DOCUMENT_NOT_IDENTIFIED` / `DUPLICATE_DOCUMENT_TYPE` / `UNRESOLVED_ERRORS`,
**404** `PROCESSING_NOT_FOUND`, **500** `OCR_UNAVAILABLE` / `PROCESSING_ERROR`.

### JSON contract notes

- Every key of `docs/AsigParse_exemplu_payload.json` is present. Extra keys are additive:
  `identity_document.expiry_date`, technical vehicle fields, `documents[]`, `field_meta.*.status/reason/checks`,
  `issues[].severity/message/suggestion`, `confirmed_at` and `disclaimer`.
- `status` is one of `needs_review`, `ready_for_confirmation` or `confirmed`. `validation.passed` is false when any
  error or warning remains (info notices don't count).
- `vehicle.legal_owner` is `null` unless C.2 was read. It is **never** copied from `certificate_holder`.
- The birth date is not derived from the CNP and is not exported. It is only used internally to cross-check the MRZ.

## 8. Layout

```
backend/
  app/
    main.py            FastAPI routes, error handlers, log redaction
    service.py         pipeline orchestration (OCR, classify, parse, validate, store) and confirm
    pipeline.py        mapping to the contract and validation rules
    schemas.py         Pydantic models (schema 1.0.0)
    ocr/               engine-neutral model, OneOCR + Tesseract adapters, registry, decoding/preprocessing
    parsing/           identity (VIZ + MRZ), registration (EU codes), shared helpers
    validation/        CNP / VIN / plate / date / fuel validators
  scripts/generate_samples.py   synthetic test documents and ground truth
  scripts/benchmark_ocr.py      engine benchmark on synthetic data -> docs/OCR_BENCHMARK.md
  scripts/benchmark_real.py     engine benchmark on local real documents -> anonymised docs/OCR_BENCHMARK_REAL.md
  scripts/setup_oneocr.ps1      copy + verify OneOCR files from the local Snipping Tool
  vendor/oneocr/                (gitignored) Microsoft OneOCR binaries
  samples/                      generated synthetic files (+ manifest.json)
  tests/
frontend/src/
  App.tsx, api.ts, fields.ts, types.ts
  components/ UploadStep, ReviewStep, FieldInput, ExportStep, QuoteDemo, ui
```
